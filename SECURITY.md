# Security Policy

## Supported work

Only releases explicitly marked as supported receive security fixes. Planned projects and archived coursework are not production services.

## Reporting a vulnerability

Use GitHub's private vulnerability reporting or a private repository security advisory when it is enabled.

If no private reporting option is visible, open a minimal public issue requesting a private contact channel. Do not include exploit details, credentials, personal data, or a proof of concept in that issue.

Include privately:

- Affected repository, version, commit, or URL.
- Impact and prerequisites.
- Reproduction steps.
- Suggested mitigation if known.
- Whether credentials or personal data may be exposed.

## Response

Reports will be acknowledged and triaged based on impact and reproducibility. No response-time commitment is claimed until a maintained release and contact process exist.

## Scope reminders

- Never test against data or accounts you do not own or have permission to use.
- Do not perform denial-of-service testing.
- Do not publish sensitive findings before remediation is available.
